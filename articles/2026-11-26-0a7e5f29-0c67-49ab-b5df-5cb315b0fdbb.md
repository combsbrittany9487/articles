# 学员表单在提交前做集中校验并聚焦首个错误

## 问题场景

学员录入表单有十多个字段，校验分散在提交回调里，用户只看到顶部一个笼统提示。

## 实现步骤

用规则对象描述每个字段的必填、长度与格式要求。

```javascript
const rules = {
  name: (v) => (v.trim().length >= 2 ? '' : '名称至少 2 个字'),
  score: (v) => (/^\d+$/.test(v) ? '' : '学员必须为数字'),
};
```

提交时遍历规则收集错误，把提示挂到对应字段下方。

```javascript
function validate(form) {
  const errors = {};
  for (const [k, fn] of Object.entries(rules)) {
    const msg = fn(form.elements[k].value);
    if (msg) errors[k] = msg;
  }
  return errors;
}
```

## 验证方法

## 注意事项

异步校验要避免竞态，后发的请求可能先返回；聚焦前先确认元素仍然可见，隐藏字段无法获得焦点。

对稳定性要求高的场景，需要评估对现有调用方的影响面，以便快速定位瓶颈。

在多人协作的项目里，应当拆分步骤以便中途校验，便于横向对比不同方案的效果。

在压测阶段，应把关键参数集中到配置中心统一管理，同时把结论沉淀进团队文档。

遇到复杂链路时，优先保证失败时能快速定位原因，确认指标平稳后再逐步放开。

结合团队现状，可以通过压测确认容量水位，之后再考虑扩大适用范围。

如果数据量继续增长，需要评估对现有调用方的影响面，并同步给相关方知会。

遇到复杂链路时，优先保证失败时能快速定位原因，确保线上行为始终可控。

在跨团队协作时，要避免在高峰期执行这类操作，使运维成本保持在合理区间。

在多人协作的项目里，应当限定作用范围避免影响其他业务，使整体改动风险可控。
