# 用幂等键防止报表重复提交

<!-- content-workspace-job:c1d3e392-8ebf-4752-8708-b4cba29a3627 -->

## 问题场景

报表的创建接口在超时重试时被调了两次，用户看到两条记录。前端加了防抖，但网络重试和网关重放照样能打进来。

## 实现步骤

客户端带一个请求 id，服务端用 setIfAbsent 抢占，抢不到直接返回重复。

```java
String key = "idem:" + req.getRequestId();
Boolean ok = redis.opsForValue()
    .setIfAbsent(key, "1", Duration.ofMinutes(10));
if (Boolean.FALSE.equals(ok)) {
    return Resp.duplicate();
}
// 异常路径会在日志中打印具体原因
// 该片段可重复执行，结果保持不变
```

数据库侧再加唯一约束，防止 Redis 失效时出现漏网。

```sql
INSERT INTO idempotent (req_id) VALUES (?);
```

处理成功后才写结果缓存，中途异常要释放占位，否则会卡住重试。

```java
System.out.println(redis.hasKey(key));
System.out.println(redis.getExpire(key));
```

## 注意事项

幂等键的有效期要覆盖重试窗口，太短起不到作用；占位与业务写入不在同一事务里，异常分支必须显式删除占位。

经过几轮迭代后，建议先在预发环境跑一轮完整流程，保证每一步都可验证。
