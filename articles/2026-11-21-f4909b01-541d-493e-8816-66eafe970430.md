# 给文件表加缓存时先挡住穿透请求

<!-- content-workspace-job:f4909b01-541d-493e-8816-66eafe970430 -->

## 问题场景

文件表的详情接口被大量不存在的 id 请求，缓存里没有就去查库，查不到又不写缓存，同一个不存在的 id 每秒打几千次数据库。

## 实现步骤

正常结果写缓存并设置过期时间，键名带业务前缀便于清理。

```bash
redis-cli SET files:1 '{"id":1}' EX 60 NX
```

空结果也写一个短过期的占位值，挡住重复的穿透请求。

```bash
redis-cli SET files:999999 '__nil__' EX 30
redis-cli GET files:999999
# 预期：命令正常返回，输出与上文描述一致
# 若出现非零退出码，先检查参数与权限
# 上述命令可重复执行，结果幂等
```

观察命中率与数据库 QPS，穿透被挡住后 QPS 应大幅下降。

```bash

```
