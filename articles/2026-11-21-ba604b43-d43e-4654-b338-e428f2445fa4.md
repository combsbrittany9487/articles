# 用 saga 编排课程的跨服务事务

<!-- content-workspace-job:ba604b43-d43e-4654-b338-e428f2445fa4 -->

## 问题场景

课程下单要跨订单、库存、支付三个服务，用本地事务包不住。中间某一步失败后，前面已经扣掉的库存没人释放，数据就对不上了。

## 实现步骤

把流程拆成若干本地事务，每一步都实现对应的补偿操作。

```java
try {
    orderService.create(o);
    stockService.lock(o);
    payService.charge(o);
} catch (Exception e) {
    payService.refund(o);
    stockService.unlock(o);
    orderService.cancel(o);
}
// 该片段可重复执行，结果保持不变
```

失败时按逆序执行已成功步骤的补偿，注意补偿本身也可能失败。

```java
void compensate(Runnable step, String key) {
    if (done.add(key)) {
        step.run();
    }
}
```

补偿必须幂等，重复执行不能产生副作用，否则重试会越补越乱。

```java
System.out.println(done.size());
System.out.println(done.contains("refund"));
```

## 验证方法

人为让支付步骤失败，库存应被释放、订单应变为已取消，最终数据一致。

## 注意事项

saga 没有隔离性，中间状态对外可见，需要业务上容忍或用状态机控制；补偿失败要有兜底对账，不能只靠重试。

结合历史事故记录，要把边界条件列成清单逐项确认，让容量规划更有依据。

上线初期，要把边界条件列成清单逐项确认，降低同类问题再次发生的概率。

在压测阶段，尽量把决策依据写进变更说明，便于横向对比不同方案的效果。

从排障效率看，要明确各项资源的释放时机，并同步给相关方知会。

经过几轮迭代后，建议先在预发环境跑一轮完整流程，保证每一步都可验证。
