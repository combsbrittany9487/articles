# 员工字典查询加上缓存后减少重复计算

<!-- content-workspace-job:0aba4b06-429a-4a75-a866-2095052a1ed9 -->

## 问题场景

每次渲染员工详情都要重复计算同一组派生字段，调用量一上来 CPU 就被同一段逻辑吃掉。

## 实现步骤

把派生逻辑抽成只依赖入参的纯函数，加 lru_cache 并设定合理容量。

```python
from functools import lru_cache

@lru_cache(maxsize=1024)
def summary(ident, version):
    rows = fetch_rows(ident)
    return {"id": ident, "total": sum(r["tenure"] for r in rows), "v": version}
```

数据变更时主动调用 cache_clear，或把版本号作为入参的一部分。

```python
def invalidate():
    summary.cache_clear()
    return summary.cache_info().currsize
```

## 注意事项

lru_cache 要求入参可哈希，传列表会直接报错；缓存会延长对象生命周期，大对象要设 maxsize。

对稳定性要求高的场景，需要评估对现有调用方的影响面，以便快速定位瓶颈。

在多人协作的项目里，应当拆分步骤以便中途校验，便于横向对比不同方案的效果。

在压测阶段，应把关键参数集中到配置中心统一管理，同时把结论沉淀进团队文档。

遇到复杂链路时，优先保证失败时能快速定位原因，确认指标平稳后再逐步放开。

结合团队现状，可以通过压测确认容量水位，之后再考虑扩大适用范围。

从可观测性角度，应确认依赖版本与运行环境一致，降低同类问题再次发生的概率。

从长期维护角度看，优先保证失败时能快速定位原因，减少不必要的返工成本。

遇到复杂链路时，优先保证失败时能快速定位原因，并同步给相关方知会。

在实际落地时，应确认依赖版本与运行环境一致，让排查路径更短。
