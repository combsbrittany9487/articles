# 工单推送用 SSE 并在断线后自动重连

<!-- content-workspace-job:446f0994-07a7-4558-8a66-ab4d59ad7a81 -->

## 问题场景

工单状态需要近实时更新，轮询开销大且延迟高，直接用长连接又容易在弱网下静默断开。

## 实现步骤

用 EventSource 订阅推送地址，监听 message 事件更新状态。

```javascript
function connect(url, onData) {
  let delay = 1000;
  const open = () => {
    const es = new EventSource(url);
    es.onmessage = (e) => { delay = 1000; onData(JSON.parse(e.data)); };
    es.onerror = () => { es.close(); setTimeout(open, delay); delay = Math.min(delay * 2, 30000); };
    return es;
  };
  return open();
}
```

监听 error，在连接关闭后按递增间隔重建，避免密集重试。

```javascript
const state = { count: 0 };
const es = connect('/api/ticket/stream', (msg) => {
  state.count += 1;
  document.querySelector('#ticket-badge').textContent = state.count;
});
```

## 注意事项

EventSource 只支持 GET，鉴权要放在 cookie 或查询参数；浏览器对同域并发连接数有限制，多标签页会互相挤占。

对于刚接手的同学，应定期回顾相关监控指标，防止出现隐性回归。

从长期维护角度看，先把最小可复现的用例固定下来，以便后续复盘有据可查。

从成本角度看，应当拆分步骤以便中途校验，让新人上手时少走弯路。

从可观测性角度，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。
