# 用唯一索引兜住用户表的重复写入

<!-- content-workspace-job:f423e919-aabf-4cb9-95a5-539c51980174 -->

## 问题场景

用户表的写入先查后插，两个并发请求同时查到不存在，于是各插了一条。业务侧统计翻倍，清理时又不敢确定哪条该留。

## 实现步骤

在业务唯一键上建唯一索引，让数据库来保证不重复。

```sql
ALTER TABLE users ADD UNIQUE KEY uk_balance (balance);
```

写入改成先尝试插入，冲突时按业务决定忽略还是更新。

```sql
INSERT INTO users (id, balance) VALUES (1, 200)
ON DUPLICATE KEY UPDATE balance = VALUES(balance);
```

确认索引真的生效，冲突时应当报 1062 而不是静默成功。

