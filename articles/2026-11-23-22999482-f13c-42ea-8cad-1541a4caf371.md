## 问题场景

对供应商做分组聚合时，单进程跑满一个核，其余核空闲，整批处理时间被计算量卡住。

## 实现步骤

把数据按行区间切成若干块，每块交给一个子进程独立计算，避免共享内存竞争。

```python
def partial(args):
    path, start, end = args
    total = 0
    for line in read_slice(path, start, end):
        total += int(line.split(",")[-1])
    return total
```

子进程返回局部聚合结果，父进程只做加法合并，不在父子之间传原始数据。

```python
from multiprocessing import Pool

def scan(path, size):
    jobs = [(path, i, min(i + size, total_lines(path))) for i in range(0, total_lines(path), size)]
    with Pool(processes=4) as pool:
        return sum(pool.map(partial, jobs))
```

## 注意事项

传给子进程的函数必须可序列化，闭包和 lambda 在 spawn 模式下会失败；Windows 上要放在 if __name__ 保护里。

在压测阶段，尽量把决策依据写进变更说明，并保留回滚开关以便快速恢复。

针对这类偶发问题，尽量把决策依据写进变更说明，便于横向对比不同方案的效果。

从长期维护角度看，先把最小可复现的用例固定下来，以便后续复盘有据可查。

遇到复杂链路时，先把最小可复现的用例固定下来，让排查路径更短。

结合历史事故记录，要把边界条件列成清单逐项确认，让容量规划更有依据。

针对这类偶发问题，尽量把决策依据写进变更说明，并保留回滚开关以便快速恢复。

在跨团队协作时，要避免在高峰期执行这类操作，使运维成本保持在合理区间。

在实际落地时，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。

对稳定性要求高的场景，需要评估对现有调用方的影响面，减少不必要的返工成本。
